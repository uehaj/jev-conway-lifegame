# Jev ライフゲーム デモ 仕様

同じ初期盤面から、Jev（TypeSafe の System One モデル jev-1.13）の判定で世代を進める3つの盤面と、正しいルールで進めた本来の経過を並べてブラウザで眺めるデモ。Jev の誤りは直さずに次の世代以降へ積み重ね、正しいルールと食い違ったセルに印を付ける。

用語はリポジトリ直下の `CONTEXT.md` に従う（盤面・初期盤面・本来の経過・端の扱い・セル・世代・判定・全盤面モード・近傍モード・カウントモード）。各項目の決定の経緯は、末尾の「決定の出典」にある ticket を参照する。

## 1. 構成

- 処理はすべてブラウザで行う。素の JS で書き、フレームワークは使わない。盤面の保持、state と質問の組み立て、正しい次世代の計算、食い違いの印はすべてブラウザの仕事である。
- `api.typesafe.ai` は CORS のプリフライトを拒否するので、ブラウザから直接は呼べない。Vite の開発サーバの proxy で中継する。
- リポジトリ直下に次のファイルを置く。`prototype-jev-probe/` は別物として残す。

| ファイル | 中身 |
|---|---|
| `package.json` | devDependency は `vite` だけ。`"dev": "vite"` |
| `vite.config.js` | `server.proxy: { '/v1': { target: 'https://api.typesafe.ai', changeOrigin: true } }` |
| `index.html` | 画面の骨組み |
| `src/` | JS と CSS |

- 起動は `npm run dev`。build は使わない（proxy は開発サーバでしか動かないため）。
- 対象は localhost での実行だけで、公開・ホスティングはしない。

## 2. 盤面と座標

- 盤面は 16×16 の固定（定数1つ）。画面では変えない。
- 座標は (行, 列) の順で、0 から数える。
- 盤面の内部表現は `"#"`（生）と `"."`（死）の行文字列 16 本の配列とする。全盤面モードの state にそのまま渡せる。
- 並べる盤面は4つ。左から順に、全盤面モード・近傍モード・カウントモード・本来の経過。4つとも同じ初期盤面から始める。

## 3. 端の扱い

- 2つから選ぶ: **外側は死**（盤面の外のセルはすべて死）と **トーラス**（上下の端と左右の端がそれぞれつながる）。起動時は外側は死。
- 4つの盤面にまとめてかける。盤面ごとには選ばない。
- 再生中も切り替えられる。効くのは次の世代から。ある世代の判定を組み立てる時点の端の扱いを、その世代の state・質問・正しい次世代の計算・本来の経過のすべてに使う。
- 近傍モードの 3×3 とカウントモードの隣の数は、コードが端の扱いに従って作る。全盤面モードは `rules` の1文を差し替えるだけで、盤面の渡し方は変えない（トーラスで全盤面モードが端で崩れても、それも見どころとして受け入れる）。

## 4. Jev への問い合わせ

### 4.1 リクエスト

1モードの1世代を1リクエストで問い合わせる。1世代で3リクエストを並列に投げる。

```
POST /v1/systemone
Authorization: Bearer <キー>
Content-Type: application/json

{ "model": "jev-1.13.0", "state": { ... }, "questions": { "c0_0": { "type": "noul", "instructions": "..." }, ... } }
```

- モデルは `jev-1.13.0` に固定する（`jev-1.13` は `400 Unknown model` になる。名前は https://docs.typesafe.ai/models.md ）。
- 質問は1リクエストに全セル分の 256 問を入れる。質問の名前は `c<行>_<列>`（例: `c3_7`）。
- SDK は使わず `fetch` で呼ぶ。

### 4.2 応答

```json
{ "model": "jev-1.13.0", "answers": { "c0_0": { "type": "noul", "noul": 0.12 }, ... }, "usage": { "input_tokens": 13500, "output_tokens": 256 } }
```

- `answers.c<行>_<列>.noul` がその質問の答え（「はい」である確率）。
- 最初の応答で `model` が `jev-1.13` で始まることを確かめる。違っていたら console に警告を出す（止めはしない）。

### 4.3 モードごとの state と質問

ルールの本文（全盤面モード・近傍モードで共通）:

```
RULES = "Conway's Game of Life. '#' is a live cell, '.' is a dead cell. " + EDGE +
  " A live cell with 2 or 3 live neighbours stays alive; a dead cell with exactly 3 live neighbours becomes alive;" +
  " every other cell is dead in the next generation. Neighbours are the 8 surrounding cells."
```

`EDGE` は端の扱いで決まる1文:

| 端の扱い | EDGE |
|---|---|
| 外側は死 | `Cells outside the board are dead.` |
| トーラス | `The board wraps around: the top and bottom edges are connected, and so are the left and right edges (the row above row 0 is row 15, and the column left of column 0 is column 15).` |

外側は死の文と、それ以外のルールの文は、プロトタイプで試したものと同じである。トーラスの文は試していない。

| モード | state | セル (r, c) への質問 | 生である確率 |
|---|---|---|---|
| 全盤面 | `{ rules: RULES, board: [16本の行文字列] }` | ``Look at `board` (row r, column c, both 0-indexed; the character `board[r][c]`). Is this cell alive in the next generation?`` | `p` |
| 近傍 | `{ rules: RULES, neighborhoods: { "r,c": [3本の3文字の行文字列], ... } }`（256 セル分） | ``` `neighborhoods["r,c"]` is a 3x3 window; its centre character is the cell. Is the centre cell alive in the next generation?``` | `p` |
| カウント | `{ n: { "r,c": 生きている隣の数, ... } }`（256 セル分） | 生のセル: ``` `n["r,c"]` is the number of live neighbours of a live cell. A live cell survives only when it has 2 or 3 live neighbours. Does this cell die?```<br>死のセル: ``` `n["r,c"]` is the number of live neighbours of a dead cell. A dead cell comes to life only when it has exactly 3 live neighbours. Does this cell come to life?``` | 生のセル: `1 − p`<br>死のセル: `p` |

- `r`・`c` には数字を埋める。
- 近傍モードの窓は、中央がそのセルで、盤面の外は端の扱いに従う（外側は死なら `.`、トーラスなら反対側のセル）。
- カウントモードの隣の数も、端の扱いに従って数える。
- カウントモードの state にはルールを置かない。質問ごとに、そのセルに関係するルールを1本だけ書く。生き残りと誕生のルールを1問に詰め込むと誤るため。

## 5. 1世代の流れ

1. 端の扱いを読み、3モードの state と質問を組み立てる。
2. 3リクエストを並列に投げ、3つとも答えが揃うのを待つ。待っている間、画面は前の世代のままにする。
3. 各モードで、生である確率が 0.5 以上のセルを生として次の盤面を作る。各セルの確率は表示のために持っておく。
4. 各モードの前の世代の盤面から正しいルールで次世代を計算し、Jev の盤面と食い違ったセルに印を付ける。
5. 本来の経過を、正しいルールで1世代進める。
6. 4つの盤面をいっせいに次の世代へ描き替え、世代番号を1つ進める。
7. 再生中なら、この世代を始めた時刻から1秒以上たってから次の世代へ進む。

- 3つの盤面は世代を揃えて進める。世代番号の表示は1つだけ。
- リセットや初期盤面の選び直しがあったら、飛んでいるリクエストは `AbortController` で取り消し、結果を捨てる。

## 6. 初期盤面

- 与え方は3つ: プリセット・ランダム・クリックで編集。
- 起動時の初期盤面はプリセット「glider + blinker」。
- プリセットは次の5つ。置く位置は左上の (行, 列)。

| プリセット | 形（`#` = 生） | 置く位置 |
|---|---|---|
| glider + blinker | glider `.#.` / `..#` / `###`、blinker `###` | glider (1, 1)、blinker (9, 9) |
| glider | `.#.` / `..#` / `###` | (1, 1) |
| R-pentomino | `.##` / `##.` / `.#.` | (6, 7) |
| pulsar | 13×13。下の図 | (1, 1) |
| LWSS | `.#..#` / `#....` / `#...#` / `####.` | (6, 9)。左へ進む |

pulsar の形:

```
..###...###..
.............
#....#.#....#
#....#.#....#
#....#.#....#
..###...###..
.............
..###...###..
#....#.#....#
#....#.#....#
#....#.#....#
.............
..###...###..
```

- ランダムは、各セルを 30% の確率で生にする。押すたびに撒き直す。割合のスライダーや seed は持たない。
- 編集は世代 0 で一時停止中のときだけできる。どの盤面のセルを押しても、共通の初期盤面のそのセルが反転し、4つの盤面に同時に映る。
- 再生中や世代 1 以降にプリセットまたはランダムを押すと、一時停止し、新しい初期盤面の世代 0 に戻る。確認ダイアログは出さない。飛んでいる判定の結果は捨てる。

## 7. 再生操作

操作バーに次を置く。

| 操作 | 動き |
|---|---|
| 再生 / 一時停止 | 1つのボタン。押すたびに切り替わる |
| 1世代送り | 一時停止中だけ押せる。1世代だけ進める |
| リセット | 最後に決めた初期盤面（編集後の盤面を含む）の世代 0 に戻る。一時停止する |
| プリセット | 5つから選ぶ（6 節） |
| ランダム | 6 節 |
| 端の扱い | 2択のボタン（外側は死 / トーラス） |
| API キー | 伏せ字の入力欄と「保存」「消去」ボタン。操作バーの端に置く |

- 速度つまみは置かない。答えが揃ったらすぐ次の世代へ進み、1世代の最短間隔は1秒で固定する。
- 判定の途中で一時停止を押したら、投げ終わった世代を反映してから止まる。ただし再試行を待っている間（8 節）に押したら、再試行を取り消してその世代の答えを捨てる。
- 自動の一時停止:
  - 1回の再生で100世代進んだら一時停止する（約 $0.2。12 節）。もう一度再生を押すと、続きからさらに100世代進む。
  - Jev の3盤面のそれぞれが「全部死んだ」か「前の世代と同じ」のどちらかになったら一時停止する。周期2以上の振動は検出しない。本来の経過はこの判定に含めない。

## 8. API キー

- 保存するのは `localStorage["typesafeApiKey"] = "<キー文字列>"` だけ。
- 「保存」で入力欄の値を保存し、「消去」で削除する。起動時は保存済みのキーを読む。
- キーが無いときは、再生と1世代送りを押せない。
- 入力欄の近くに注意書きを1行出す: 「キーはこのブラウザの localStorage に平文で保存されます」。

## 9. エラーのときの扱い

根拠は https://docs.typesafe.ai/api.md の Errors（429・529 は指数バックオフで再試行する）。キー無しで実際に返ったのは 403 だった。

| 種類 | 再試行 | 諦めたら |
|---|---|---|
| `401` / `403`（キー） | しない | 一時停止し、キー欄の横に「キーが無効です」 |
| `422` / その他の `4xx` | しない | 一時停止し、エラー本文を表示 |
| `429` / `529` / `5xx` / ネットワークエラー / タイムアウト（30秒。`AbortController` で切る） | 最大3回。`Retry-After`（`retry-after-ms`）があれば従い、無ければ 1秒 → 2秒 → 4秒 | 一時停止 |
| 応答の `answers` に、どれかのセルの `noul` が数値として無い | しない | 一時停止し、「答えが欠けています」 |

- 3モードのうち一部だけ失敗したら、成功した答えは持っておき、失敗したモードだけを投げ直す。
- 一時停止したら、その世代の答えはすべて捨てる。再生を押したら3つとも投げ直す。
- 知らせ方: 操作バーの下にステータスを1行出す（例: 「近傍モード: 429 レート制限、再試行 2/3（2秒後）」）。次の世代に進めた時点で消す。盤面の見出しには出さない。
- 1世代送りのときも、再生中と同じ規則に従う。

## 10. 表示

### 並べ方

- 4つの盤面を横一列に並べる。1セルは 20px。幅が足りなければ折り返す。
- 各盤面の見出しは、モード名と、Jev に何を渡しているかの説明1行だけにする。セル数や食い違いの数は出さない。

| 盤面 | 説明の1行（例） |
|---|---|
| 全盤面モード | 盤面全体とルールを渡す |
| 近傍モード | セルの周り 3×3 とルールを渡す |
| カウントモード | 生きている隣の数を渡し、死ぬか / 生まれるかを聞く |
| 本来の経過 | 正しいルールで進めた盤面（Jev は使わない） |

- 世代番号は操作バーに1つだけ出す。

### セルの塗り

- 生と死で濃さの範囲を分け、その中で確率を濃淡にする。p は生である確率。
  - 生（p ≥ 0.5）: 濃さ 60〜100%（p = 0.5 で 60%、p = 1 で 100%）
  - 死（p < 0.5）: 濃さ 0〜40%（p = 0 で 0%、p → 0.5 で 40%）
  - 40〜60% の段差で生死はひと目で分かり、自信のなさは「生なのに薄い / 死なのに濃い」として見える。
- 世代 0 と本来の経過は、確率を持たないので2値（100% / 0%）で塗る。

### 食い違いの印

- Jev の3盤面で、正しいルールと食い違ったセルに赤い枠を1種類だけ付ける。どちら向きの誤りかは塗りで読み取る。
- 比べる相手は「その盤面の1つ前の世代から、その世代の端の扱いで正しく進めた盤面」である。本来の経過と比べるのではない。
- 本来の経過と世代 0 には印を付けない。

### ツールチップと凡例

- セルにマウスを重ねると、Jev の3盤面では「(行, 列) 生である確率 0.62 / 正解: 生」を出す。世代 0 と本来の経過では「(行, 列) 生」のように座標と生死だけを出す。
- 盤面の下に凡例を1行出す: 「濃い = 生 / 薄い = 死 / 濃さは Jev の自信 / 赤枠 = 正しいルールと食い違い」。

## 11. 範囲外

- 盤面の保存・共有（パターンの保存、URL での共有）。
- Jev 以外のモデルとの比較。
- インターネットへの公開・ホスティング。
- 正答率の数値集計・グラフ（食い違ったセルに印を付けるところまでが対象）。

## 12. 参考: 見積り

プロトタイプ（8×8）の実測から見積もった値。

- 入力トークン: 1セルあたり 全盤面 約 53 / 近傍 約 70 / カウント 約 61。16×16 では3モードとも1リクエスト 1.8万トークン以下で、上限（合計 64k、state は 32k）に収まる。
- 所要時間: 1リクエスト 0.2〜0.8 秒。3モードを並列に投げれば1世代は1秒弱。
- 費用: 入力 100万トークンあたり $0.042。16×16・3モードで1世代 約 4.7万トークン（256 × (53 + 70 + 61)）なので 約 $0.002、100世代で 約 $0.2。「初期盤面と再生操作」で書いた「約 $0.08」は少なく見積もっていた。
- 見え方（8×8・5世代）: 全盤面モードは glider が止まり行が伸びる。近傍モードは2世代目でかたまりになって止まる。カウントモードは blinker は正しく回り、glider は途中の1マスの誤りからずれていく。
